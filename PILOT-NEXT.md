# RITM NEXT LEVEL · P0, редакция 2
Внутренний серверный комплект для тестовых профилей. Предыдущая сборка cfbb3bb сохранена. На телефонах испытания ожидают двух доступных устройств.

## Запуск и воспроизведение
Для самого стенда нужен Python 3.10+. Из корня распакованного комплекта выполните «python web/server.py --port 8765». На этом компьютере откройте http://127.0.0.1:8765/ . Инструкция для двух телефонов приведена ниже в первой редакции.

Для полного набора проверок этой серверной сборки на Windows используйте чистую папку и новое Python-окружение. Браузерные движки устанавливаются один раз.

    python -m venv .venv
    .venv\Scripts\python -m pip install -r requirements-pilot-tests.txt
    .venv\Scripts\python -m playwright install chromium webkit
    .venv\Scripts\python tests/run-pilot.py review

Проверки используют временные БД и локальные порты. Команда завершается с ошибкой при первом упавшем тесте. В поставку включены analysis/sales.py, analysis/choice-funnel.py, модуль импорта событий и SQL для аналитики. Набор включает правила, CHOICE, коммерческие сезоны, криптографию Web Push, аналитические метрики, браузерный обмен двух профилей, дневники в Chromium и WebKit и восстановление копии. Исторические визуальные прогоны статических Founder/UX Preview относятся к прежним сборкам в репозитории.

## Изменения
В тренировке таблица подходов позволяет перенести вес и повторения из любой строки, скорректировать их кнопками и записать следующий подход. Отдых настраивается в раскрывающейся панели. Питание показывает кольцо вклада макронутриентов в энергию и фактическую калорийность по этикетке. Ввод и правка вынесены в нижнюю панель. Аналитика показывает график по дням либо пятидневным интервалам и сравнение с предыдущим равным периодом при наличии записей. Вес — максимум упражнения, объём — сумма кг × повторения. Фотографии иллюстрируют раздел. Анатомические схемы и обучающие ролики конкретного упражнения требуют проверенного и лицензированного материала. Каталог с фильтрами, DUO 28 и контекстные переходы к сопровождению сохранены.

## Офлайн и устройства
Оболочка и необходимые для тренировки статические ресурсы предварительно кэшируются через service worker. При потере сервера приложение открывает локальную копию активного занятия; очередь подходов отправляется с прежними идентификаторами. Для начального заполнения кэша нужен один визит с сетью в этом браузере или установленной PWA. Приватный режим, очистка сайта, удаление приложения и вытеснение хранилища ОС могут удалить локальные записи. Для проверки на телефоне нужны доверенный HTTPS и тестовые профили. Браузерный тест действительно останавливает процесс сервера, закрывает вкладку, открывает новую при выключенном сервере и вновь запускает процесс с той же базой. Настоящие Safari на iPhone и установленная с домашнего экрана PWA требуют отдельного прогона.

# RITM Premium Athletic · внутренний пилот
27 ноября 2026. Для испытаний используйте вымышленные имена и тестовые записи.

## Запуск
Распакуйте ZIP. Требуется Python 3.10 или новее. Из корня комплекта выполните команду

    python web/server.py --port 8765

Откройте http://127.0.0.1:8765/ . Закрытие процесса останавливает стенд. При следующем запуске профиль и записи остаются в web/pilot-local.sqlite. Каждый браузер получает отдельный профиль. Для восстановления на другом устройстве заранее сохраните одноразовый код в разделе настроек. При переносе предыдущий доступ отзывается.

Для проверки двумя телефонами в доверенной Wi-Fi сети запустите тот же сервер с параметром --host и локальным IPv4 компьютера. Оба телефона должны открыть одинаковый адрес компьютера с портом 8765. Начинайте CHOICE с этого адреса, чтобы приглашение тоже содержало доступный телефону адрес. Для проверки установленной PWA и холодного запуска без сети на телефоне требуется доверенный HTTPS. Обычный HTTP по Wi-Fi подходит для проверки обмена тестовыми приглашениями. Комплект не открывает порт маршрутизатора и не меняет системный брандмауэр.

## Что проверить по порядку
1. Откройте PULSE в профиле А, создайте CHOICE из двух вариантов, передайте ссылку профилю Б. Б выбирает действие для А. А выполняет его, Б получает результат и может предложить обратный ход. Повторный переход сохраняет прежний ответ. Проверьте путь отдельно от совместной активности и дуэли.
2. В «Тренировках» откройте дневник. Введите два упражнения из своего тестового плана, каждое с новой строки. Запишите вес, повторения и отдых. При разрыве сети подход попадает в очередь на устройстве. После возврата связи журнал отправляет его с прежним идентификатором. Перейдите к следующему упражнению, пропустите его или завершите сессию частично. История доступна из дневника.
3. В «Питании» откройте дневник. Укажите дату, продукт, массу и четыре значения с этикетки на 100 г. Для 90 ккал, Б 4, Ж 2, У 14 порция 150 г даёт 135 ккал, Б 6, Ж 3, У 21. Измените массу на 200 г и проверьте 180 ккал, Б 8, Ж 4, У 28. Удалите тестовую запись и проверьте итог дня.
4. На главной откройте «Мой прогресс». Проверьте периоды 7, 30 и 90 дней, дату, подходы, рабочий вес выбранного упражнения и объём. Два подхода по 12,5 кг × 8 дают 200 кг объёма. Считаются завершённые и частичные сессии. Ноль у нового профиля означает отсутствие записей.
5. Для внутренней проверки людьми фиксируйте отдельно устройство, версию ОС, браузер/PWA, действие, ожидаемый результат, фактический результат и потребовалась ли подсказка. Первый самостоятельный обмен CHOICE можно проверить до остального пилота.

## Протокол
* Проверены независимые браузерные контексты, гостевой выбор без регистрации, обратный CHOICE, результат автору, индивидуальная награда в приглашении на дуэль, одноразовый перенос профиля, отзыв старой сессии и запрет доступа к чужому дневнику.
* В Chromium проверены новая тренировка, два подхода, очередь без сети, перезагрузка без сети, синхронизация при возврате, смена и пропуск упражнения, частичное завершение. В WebKit проверены запись при разрыве связи и повторное открытие с сетью. Попытка полной перезагрузки без сети в WebKit на Windows вернула ошибку самого движка навигации. До проверки в Safari на физическом iPhone этот сценарий открыт.
* Проверены перерасчёт КБЖУ, исправление массы, удаление, смена периода и показатели по фактическим подходам. На экранах снимков проверена ширина 375, 390 и 430 CSS px. Снимки сделаны при 390 × 844. Это автоматические проверки, очная проверка двумя людьми ещё ожидается.
* Серверные тесты check-choice (6), check-rules и check-season проверяют в том числе повторы, срок действия, приватность, правила дуэлей, правила учёта оплаты и возврата. Подпись и шифрование push проверены с тестовым ключом и локальным получателем, доставка реальному устройству не проверена. Резервная копия SQLite открыта отдельно, пройдены integrity_check, foreign_key_check и сравнение содержимого всех 31 таблиц.
* Для повторения браузерных тестов нужен Python Playwright с Chromium и WebKit. На выделенной тестовой базе запустите tests/next_exchange.py и tests/next_diaries.py с аргументами URL сервера и существующая папка снимков. tests/next_backup.py принимает путь к тестовой базе. Для WebKit добавьте webkit --connected-reopen для прогона с восстановлением сети перед перезагрузкой.
* На этом этапе нет результатов пилота пяти пользователей, физического iPhone и Android, тестовой покупки через эквайера, промышленной проверки изоляции, аудита прав или замеров доступности сервера. Витрина, фильтры, DUO 28 и заявки сохранены. Распределение экспертного продукта 30/70. Платные сервисы и реальный эквайринг отключены.
* В журнале подходов доступны фактический вес и повторения. Каталог проверенных упражнений с видео, анатомия, утверждённые замены, отдельный учёт разминки и упражнений на время ещё требуют проработки. Дневник питания использует ручную запись с этикетки. Одноразовый код переносит доступ между устройствами. Постоянные параллельные входы в один аккаунт ещё не поддерживаются. Синхронизация двух разных людей работает через один сервер.
* Очередь и черновик тренировки хранятся в локальном хранилище браузера. Очистка данных устройства до синхронизации удаляет неотправленные подходы. Стенд предназначен для синтетики.

## Сверка сметы и условия для согласования
Источник — книга «RITM — финансовая модель 36 месяцев.xlsx», лист «Бюджет и часы». Базовая смета десяти пар равна 1 000 + 3 000 + 125,25 + 5 000 = 9 125,25 ₽. Диапазон 7 600–13 000 ₽ включает только 2 × (1 300–4 000) и 5 000 ₽ фонда. Для сопоставления с прежней моделью прибавляем 1 000 ₽ запуска и 125,25 ₽ переменных, если они оплачиваются отдельно. Итого 8 725,25–14 125,25 ₽. При включении переменных в тариф сумма 8 600–14 000 ₽. Базовый сценарий модели укладывается при 1 500 ₽/мес. Расчётная трудоёмкость P0 — 184–320 часов. Собственный неоплачиваемый труд учитывается в часах. Денежный расход этой разработки на новые сервисы и инфраструктуру — 0 ₽.

Ориентир хостинга с резервированием — 1 500 ₽/мес., верхний бюджет и поставщика утверждает основатель после получения предложения.
